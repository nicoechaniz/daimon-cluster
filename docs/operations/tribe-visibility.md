# Native visibility maintenance

For an already prepared visibility successor, run one foreground command:

```sh
sudo python -B -I tools/tribe_visibility.py --request /protected/visibility-request.json
```

Use the owning environment with the installed Matrix SDK and the existing
`cluster-maintenance-reader-routes/v1` physical-placement registry. The private
request retains the exact existing operation, seven-member disclosure, owner
locators, publication predecessor hashes, current reader checkpoint and a bounded
result path. Preparation uses existing owner publication descriptors and SDK/code
qualification; it does not recreate membership or keys.

The command collects the actual native acceptances, applies only missing
publications, restores each scoped Matrix service and completes the current
cohort through its existing reader controls. Remote reader jobs use the registry's
existing backend, not a local execution of a remote path. There is no model call,
goal change, global Stop or permanent attention service. Existing protected native
and voice processes remain untouched.

Repeat the same command to finish missing effects. Completed owner receipts are
reconciled, never republished; changed later selections are preserved. Finite
owner jobs survive a carrier disconnect and have an operation-owned Matrix
restoration callback. An uncertain owner result remains a concrete failure to
inspect, not permission to create a replacement operation. The private result
records actual publication and cohort completion. A message delivery/response is
still its own actual result; an enabled lane or selected service does not prove it.
