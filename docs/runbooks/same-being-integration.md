# Finite same-being integration

Cluster #296 connects the merged DMK native exchange, selective Skills installer
and behavioral adapter to actual Matrix proposals, local adoption and observed
projection receipts. It belongs to [Matrix #376](https://github.com/AlterMundi/daimon-matrix/issues/376).
Source publication and fixture success do not establish installed SDK selection,
real two-body retrieval or model consumption. Keep those receiving gaps explicit.

Use the receiving operator, not an onboarding renderer, whole-database restore,
curator job or peer executor:

```sh
python -m clusterctl.same_being_operator --binding RECEIVING.json \
  inspect --source-event-id EVENT_UUID
python -m clusterctl.same_being_operator --binding RECEIVING.json \
  prepare --operation-id UUID --selection SELECTED.json
python -m clusterctl.same_being_operator --binding RECEIVING.json \
  apply --operation-id UUID
```

`inspect` returns proposal hashes/local decision without adopting. `recover`
resumes the same parent and its exact retained requests; `status`
reobserves actual children. `rollback` retains an inverse local decision and
restores unchanged selected skills/configuration through their owning inverses.
It deliberately retains attributed imported memory, history and concurrent writes.
The original application remains history. After rollback begins, `apply` refuses
to recreate its former effects. Partial application remains resumable; completed
parents support controls rollback. Preserve unresolved/conflicting children rather
than describing a partial inverse as complete or restoring an old memory snapshot.

The private receiving binding uses `cluster-same-being-binding/v1` and exactly
`schema`, `binding`, `journal`, `matrix`, `memory`, `skills`, `behavior`:

- `binding`: the verified local being/body/embodiment/incarnation/principal tuple.
- `journal`: the existing owner-controlled OperationJournal directory.
- `matrix`: existing `socket`, `client_config`, `key_file`, optional
  `timeout_seconds`. Reuse the issued weave capability; do not copy credentials
  into selection documents. Old unresolved signed requests still require their
  original matching client profile, nonce and authentication bytes.
- `memory`, or null: selected `scripts`, `files` (relative executable/helper
  names to exact SHA256), receiving `environment`, DMK `owner` including
  `pool_lineage`, and existing `backup_config`. Optional `legacy_provenance` and
  `legacy_provenance_sha256` select DMK's own retained legacy adapter. The
  environment names are the existing HMK receiving names; only explicitly
  supported memory paths are accepted. The loader restores process environment
  after resolving the owning module. Use it during trusted bootstrap, before
  concurrent service work; different already-loaded helper bytes are refused.
- `skills`, or null: existing `installer`, its `installer_sha256`, source
  `repository`, receiving `root` and installer `state`. The immutable descriptor
  selects exact source Git/package bytes. Pending recovery is scoped to the exact
  plan under the installer's lock; an unrelated pending transaction is preserved.
- `behavior`, or null: optional receiving `native_control_socket`, `native_file`
  and `cwd`. Without a native client only selected owned files are supported.

The trusted host calls `load_operator(RECEIVING, matrix=existing_client)` once and
injects its `observe_effect` through Matrix's existing `load_runtime` keyword
`projection_observer`. It is never selected from an RPC, proposal or packet.
The observer resolves this local journal and actual child owners, with no Matrix
re-entry, peer path lookup or model call. A normal CLI uses the existing daemon;
it does not load custody/runtime outside the daemon lock. Before child effects,
the parent requires both the actual issued receipt method and receiving status
reporting the trusted observer available. Do not claim this bootstrap deployed
merely because the source seam exists.

Native configuration uses the existing Codex daemon control WebSocket and only
`config/read` or `config/batchWrite`, plus protocol initialization. Codex 0.163
advertises a rendezvous symlink: resolve and validate its protected physical
owner-only socket before connecting. It is not a plain NDJSON socket. No new
daemon, native session, model turn or credential is created. Selected native
writes reuse the behavioral adapter's exact user-layer CAS/reload contract.

The private selection contains `source_event_id`, an explicit local `reason`, and
one or more of `packets`, `skill_plan`, `behavior_selection`. Behavioral selection
uses the adapter's verified source tuple, exact `source_refs`, local `files`
(absolute destination to base64 bytes or null), optional native `edits`.
`behavior_sources` maps those SHA256 refs to the original base64 bytes; local
rendered destinations are separate. Optional `residual` retains deliberate,
conflicting, unavailable or unsupported delta. All chosen packet/descriptor/
behavior hashes must occur in the exact known same-being proposal. Source paths
and prose never choose a receiving destination, executable or capability.

Preparation validates packet closure against the initial receiving inventory,
preserves behavioral preimages and retains one content-bound parent. Application
uses one existing DMK pre-write checkpoint, deterministic memory children, the
native skill transaction and one behavioral child. Cross-page links may remain
pending between pages; completion requires their actual resolution. Original
signed adoption/receipt requests are retained before dispatch; losing a return
does not mint another request, event or effect. Matrix reconciles fresh receiving
truth on exact receipt retries, preserving historical events when state changes.

CLI output contains observed summaries, hashes and state, not originals, private
paths, credentials or request authentication. Binding/selection/journal files
remain owner-private. The whole selection is bounded to 128 MiB; DMK retains its
own tighter packet and transaction bounds. No automatic journal retirement is
authorized. Saved/read-back/reloaded settings report consumption **unverified**;
actual receiving harness use must be established separately on both bodies.
Residual originals stay in the private selection; status exposes only their count
and digest. Error output accepts explicit maintained domain codes, never arbitrary
exception prose even when it resembles an identifier. A kill during native skill
rollback resumes only that retained `rolling_back` transaction under the owning
lock, then verifies all selected preimages; unrelated transactions are untouched.

## Qualification and receiving boundary

CI's `integration` profile runs affected journal/behavior/operator contracts and
a separate real composed journey with exact Matrix/DMK/Skills source revisions.
The standalone generic Skills installer is retained byte-for-byte under
`support/skills-update`, with source commit/blob and SHA256 provenance. It remains
owned by Skills and is not a fork or a copy of the skill collection. Public CI
verifies those exact bytes rather than requiring cross-repository access to the
private collection or adding a credential. Refresh it from its owning source
when its selected contract changes.
It does not replace the normal installed Matrix pin. Shared/unknown changes retain
the full profile, including the composed journey. Local execution can supply
`SAME_BEING_MATRIX_SOURCE`, `SAME_BEING_DMK_SCRIPTS`, `SAME_BEING_SKILLS_SCRIPT`
and put the selected Matrix `src` on PYTHONPATH. Missing sources explicitly skip
the optional local composed cases; CI supplies all three rather than counting
those skips as success. The journey uses native SQLite/history/checkpoints,
actual Git installation, behavioral effects, authenticated Unix transport and
the trusted host observer. It includes a real SIGKILL after a live skill move,
lost returns, conflicting later edits, exact replay and compatible inverse.

With `BEHAVIOR_NATIVE_BINARY` set to an exact receiving Codex executable, the
additional isolated native tests prove stdio and protected WebSocket config
behavior. They create synthetic homes and only fixture-owned servers, never a
model or a live configuration change. Ordinary CI without that binary retains
the explicit native-test gap instead of claiming actual harness proof.

Deploy the compatible SDK/client profile, DMK selection and this trusted host
binding through their maintained receiving routes. Preserve original generations,
profiles, memory and sessions. Capture each body's exact harness/version default
before applying its selected delta. An offline body remains pending; local
source qualification is not its installed/adopted/consumed receipt. No global
Stop, account/access change, background attention or cross-being memory pooling
is implied.
