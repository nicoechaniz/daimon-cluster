# Publishing an own HTTP application

Use the installed `daimon-home-service` command and your existing Home publisher
binding. Select an immutable own broker package, exact previous digest, audience
and App metadata in a private deployment request. The command deploys and
publishes through your existing Home identity; it does not require a new login.

Run the same request again after an interrupted reply; never replace its ID to
hide an uncertain outcome. A retained completion describes that original
operation. Do not claim human-device acceptance from an operator result.

The receiving operator must have selected a capability for your own service.
That capability supplies destination, runtime, bounded state and resources,
restricted listener and protected route. Your publication credential does not
by itself authorize installing code or changing infrastructure. A missing
capability is a concrete receiving configuration task under the human request,
not a request for a peer approval or another account.

Keep application state outside the immutable package. A compatible rollback
selects the retained previous package with a new, explicitly selected request
and actual current digest; it never resets data. Keep your original native work,
memory, accounts and Home publications intact.

See the maintained Cluster `docs/runbooks/home-service-deployment.md` for the
exact request/package contract, resource bounds and supported recovery. This
pointer is installed with the qualified owner command through the existing
publisher update route, not a startup hook or autonomous publishing instruction.
