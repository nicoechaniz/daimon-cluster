# Expired native local profiles

A live signed body can outlive a finite local operator capability. A native
process, an open proxy port and retained reader selection do not prove current
message reception. Inspect the actual authenticated status and receiving HTTP
listener. Preserve original uncertain sends; repairing a listener is not evidence
of their delivery and must not create replacement speech.

For V8 original-profile expiry use Matrix's existing explicit owner transaction:
`operator_runtime_upgrade.stage_capabilities` with `add_methods={}` and
`profile_renewal_not_after_ms`, then its exact `publish-capabilities` receipt.
Keep the current signed body authority, keys, methods, native histories and
monotonic custody counter. Fence only the selected Matrix writer. Never edit
capability JSON, substitute the clock or restore the expired bundle as rollback.
See Matrix `docs/runbooks/operator-capability-upgrade.md` for the native contract.

The receiving Target compares the current signed complete capability set to its
historical activation record. Same-key, same-method expired-profile renewal is
compatible history evolution. This comparison authenticates current descriptors
and their embodiment signature; it does not renew a role or grant execution.
Method/key/status/profile changes remain rejected. Current load, group selection,
all-required reader qualification and actual delivery are separate observations.

Use the existing critical-service observer for live status and approaching local
role expiry. Do not add another inbox reader or model attention to monitor health.
A generic owner-action refusal must be diagnosed with bounded exception classes
and code locations, never arbitrary exception strings or credentials.
