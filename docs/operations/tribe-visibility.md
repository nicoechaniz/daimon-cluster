# Native visibility maintenance

For an already prepared visibility successor, run one foreground command:

```sh
sudo python -B -I tools/tribe_visibility.py --request /protected/visibility-request.json
```

Use the owning environment with the installed Matrix SDK and the existing
`cluster-maintenance-reader-routes/v1` physical-placement registry. The private
request retains the exact existing operation, seven-member disclosure, owner
locators, publication predecessor hashes, current reader checkpoint and a bounded
result path. Preparation uses existing owner publication descriptors and SDK/code
qualification; it does not recreate membership or keys.

The command collects the actual native acceptances, applies only missing
publications, restores each scoped Matrix service and completes the current
cohort through its existing reader controls. Remote reader jobs use the registry's
existing backend, not a local execution of a remote path. There is no model call,
goal change, global Stop or permanent attention service. Existing protected native
and voice processes remain untouched.

The same request may include `native_updates`, a list of existing root-owned
native-profile or admitted-body maintenance specs, and each owner's qualified
`launch` and `expected_sdk_wheel`. The command resumes those existing native
journals first, checks actual loaded code/SDK through the configured owner
clients and pins each selected Matrix process before arming publication. It
creates its own scoped metadata; no separate prepare/finalize launches are needed.
Completed native updates and armed metadata are retained across interruption,
so a publication-owned stopped service does not cause an earlier software update
to be repeated. Later selectors still win at the existing service fence.

Finite owner units use operation-specific names and systemd collection after
completion. A later release cannot collide with an earlier completed helper;
receipts and native journals, rather than an idle helper unit, retain the result.

Repeat the same command to finish missing effects. Completed owner receipts are
reconciled, never republished; changed later selections are preserved. Finite
owner jobs survive a carrier disconnect and have an operation-owned Matrix
restoration callback. An uncertain owner result remains a concrete failure to
inspect, not permission to create a replacement operation. The private result
records actual publication and cohort completion. A message delivery/response is
still its own actual result; an enabled lane or selected service does not prove it.

A signed native SQLite BUSY/LOCKED rejection during reader selection is reconciled
once with the same durable request and original effect deadline. Other refusals,
repeated contention and uncertain transport results remain retained failures;
they do not trigger new controls or an automatic maintenance loop.

Cold native startup has one180-second parent readiness envelope, including SDK,
identity/application preparation and listener recovery. A caller-supplied earlier
deadline still wins; phases do not restart the clock. The SDK retains its own
shorter reader-journal recovery cap, and normal RPC/control/credential deadlines
are unchanged. Actual readiness, not a successful service start, completes the
receiving qualification. This permits cold preparation before recovery; it does
not compact an ever-growing signed journal or remove any verification.
